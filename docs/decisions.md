## قرار 1: استخدام AzuraCast بدل بناء النظام من الصفر
- **التاريخ:** 2026-11-22
- **القرار:** AzuraCast (منصة راديو مفتوحة المصدر تجمع Icecast + Liquidsoap + لوحة إدارة ويب).
- **السبب:**
  - يغطي المتطلبات السبعة كلها: بث مباشر، مركزية، AutoDJ للاستمرارية، إدارة المحتوى، جدولة حسب الساعات.
  - مجاني ومفتوح المصدر وناضج، ويتركب بـ Docker.
  - يخليني أركز على المعمارية والتشغيل والتوثيق بدل إعادة اختراع العجلة خلال 4 أيام.
- **البدائل اللي رفضناها:**
  | البديل | ليش رفضناه |
  |---|---|
  | Icecast + لوحة تحكم أبنيها بـ FastAPI | الوقت (4 أيام) ما بيكفي لبنائها بجودة ثابتة، ومخاطرة أعلى |
  | منصة جاهزة (SaaS) مثل Zeno.fm | ما في معمارية سحابية أشرحها، وقيود وإعلانات بالمجاني |
  | بث HLS عبر CDN | تأخير أعلى (10–30 ثانية) وتفاوت أكبر بين الأجهزة، وهذا عكس متطلب التزامن |
  | تزامن مخصص بـ WebSocket | مش راديو حقيقي، ومشاكل autoplay، وبناء كامل من الصفر |

## قرار 3: الـ Home Region = Saudi Arabia West (Jeddah)
- **التاريخ:** 2026-11-23
- **القرار:** Jeddah (me-jeddah-1). البديل الأول إذا ما في سعة: UAE East (Dubai).
- **السبب:**
  - قريبة جغرافياً من الأردن، فالتأخير الشبكي قليل (تقريباً 40–60ms).

  - التأخير الشبكي واحد لكل الفروع، فما بيأثر على التزامن بينها. الأهم إن يكون فيها سعة لسيرفرات ARM.

  | Dubai / Abu Dhabi / Riyadh | خيارات قريبة ومناسبة كمان. Dubai هي البديل الأول |
- **ملاحظة:** الـ Home Region ما بتتغير بعد التسجيل، والموارد المجانية بتشتغل فيها بس.

## قرار 4: الدومين = ghammas-radio.duckdns.org (DuckDNS)
- **التاريخ:** 2026-11-23
- **القرار:** دومين فرعي مجاني من DuckDNS.
- **السبب:**
  - رابط مرتب وسهل للجنة والفروع بدل أرقام IP.
  - ضروري للحصول على شهادة HTTPS مجانية من Let's Encrypt.
  - مجاني، وبنقدر نحدّث الـ IP بسهولة إذا تغير السيرفر.
- **البدائل:**
  | البديل | ليش ما اخترناه |
  |---|---|
  | استخدام الـ IP مباشرة | شكل غير احترافي، وما بنقدر ناخذ شهادة HTTPS عادية عليه |
  | sslip.io / nip.io | بيشتغل، بس الاسم بيحتوي على الـ IP وشكله غير مرتب |
  | دومين مدفوع (مثل .com) | حوالي 10$ بالسنة. هو الخيار الأفضل للتشغيل الفعلي لاحقاً، بس مش ضروري للتاسك |
- **ملاحظة:** الـ IP الحالي بالسجل هو IP البيت (DuckDNS حطه تلقائياً)، ورح نغيره لـ IP السيرفر لما ننشئه.

## قرار 5: الانتقال لـ Google Cloud (Free Trial) كمزود أساسي
- **التاريخ:** 2026-11-23
- **السبب:** حساب Oracle انحظر مؤقتاً (Rate Limiting) أثناء تفعيل الـ MFA، والتسليم يوم الخميس، ووقت انتهاء الحظر مجهول (التفاصيل بـ challenges.md).
- **القرار:** Google Cloud مع رصيد التجربة المجانية (300$ لمدة 90 يوم)، على سيرفر e2-medium (2 vCPU / 4GB RAM) بنظام Ubuntu 24.04.
- **ليش هالمواصفات؟** AzuraCast بيحتاج 2GB كحد أدنى و4GB موصى فيها. الـ e2-micro المجاني للأبد (1GB) ما بيكفي.
- **التكلفة الفعلية علينا: صفر.**
  - حساب التجربة **ما بيخصم من البطاقة تلقائياً**. وإذا خلص الرصيد أو المدة، بيتوقف الحساب، إلا إذا فعّلنا الحساب المدفوع يدوياً (وما رح نعمله).
  - التكلفة التقديرية (سيرفر + قرص + IP ثابت) تقريباً 35–45$ بالشهر، وبتنخصم من الرصيد.
  - عملنا Budget Alert للمراقبة.
- **ليش التبديل ما أثر على التصميم؟** لأن AzuraCast مبني على Docker، فالنظام **Cloud-Agnostic**، يعني نفس خطوات التركيب بتشتغل على أي سيرفر Ubuntu.
- **مقارنة سريعة:**
  | | Oracle Always Free | Google Cloud Free Trial |
  |---|---|---|
  | الموارد | 2 OCPU / 12GB (ARM) | e2-medium 2 vCPU / 4GB (x86) |
  | المدة | للأبد | 90 يوم أو 300$ |
  | الجدار الناري | جداران (Security List + iptables) | جدار واحد (VPC Firewall Rules) |
  | الدخول للسيرفر | SSH Key | SSH من المتصفح مباشرة أو SSH Key |
- **الخطة الاحتياطية:** حساب Oracle الحالي بيضل احتياط، وما رح نعمل حساب ثاني لأن الشروط بتمنع ذلك.

## قرار 6: AWS (Free Plan) كمزود أساسي حالياً
- **التاريخ:** 2026-11-23
- **السبب:**
  - Google Cloud رفض تفعيل التجربة (OR_BACR2_59)، وبعدها طلب دفعة مسبقة 30$، فرفضنا.
  - Oracle لسه محظور مؤقتاً بالـ MFA.
- **القرار:** حساب AWS على **Free Plan**، والتسجيل صار عن طريق **Google (SSO)**.
- **ليش Free Plan؟**
  - 100$ رصيد فوراً (وممكن توصل 200$)، لمدة لحد 6 شهور.
  - **ما في أي خصم من البطاقة** إلا إذا رقّينا الحساب لـ Paid plan يدوياً. لما يخلص الرصيد أو المدة، الحساب بيتسكّر لحاله. يعني صفر مخاطرة مالية.
  - التحقق من البطاقة كان حجز 1$ بيرجع خلال 3–5 أيام.
- **ليش التسجيل بـ Google (SSO)؟** ما بنحتاج كلمة سر جديدة، والتحقق بخطوتين بيتولاه Google، فتجنبنا مشكلة MFA اللي صارت مع Oracle.
- **مميزات AWS للتاسك:** الأكثر استخداماً بسوق العمل، وجدار ناري واحد (Security Groups)، ودخول للسيرفر من المتصفح (EC2 Instance Connect).
- **العيب:** مش مجاني للأبد. بس المدة (6 شهور) أكثر من كافية للتقييم والمقابلة الثانية.
- **Oracle:** بيضل احتياط، وبنجربه بكرة الصبح.

## قرار 10: تكبير السيرفر لـ 4GB (c7i-flex.large) مع خطة تصغير
- **التاريخ:** 2026-11-23
- **القرار:** بعد ما يخلص التركيب، بنعمل **Vertical Scaling** من t3.small (2GB) لـ **c7i-flex.large (4GB)** للفترة اللي فيها التقييم والمقابلة الثانية.
- **السبب:** أداء مريح وثابت وقت تجربة اللجنة، ومعالجة ورفع الأغاني أسرع، وما في خطر تعليق.
- **الثمن:** الرصيد بيخلص أسرع (تقريباً شهر ونص بدل 5 شهور).
- **إدارة المخاطرة:**
  - Budget بيبعت تنبيهات بالإيميل.
  - **بعد المقابلة الثانية بنرجع لـ 2GB**، فالرصيد بيطوّل لشهور.
  - الـ Elastic IP ثابت، فالرابط ما بيتغير مع التكبير أو التصغير.
- **المبدأ:** Right-Sizing و Vertical Scaling بالاتجاهين، يعني بنكبّر وقت الحاجة وبنصغّر لتوفير التكلفة.
- **الأرقام الفعلية من AWS (Stockholm):**
  | | t3.small | c7i-flex.large |
  |---|---|---|
  | السعر | 0.0216$/ساعة (تقريباً 16$/شهر) | 0.0908$/ساعة (تقريباً 66$/شهر) |
  | الرام | 2GB | 4GB |
  | الشبكة | لحد 5 Gbit | لحد 12.5 Gbit |
  | Burstable | نعم (أداء متقطع حسب رصيد CPU) | **لا (أداء ثابت)** |
  - مع القرص والـ IP، التكلفة تقريباً 72$/شهر، يعني رصيد 120$ بيكفي حوالي 50 يوم.
  - **ملاحظة Burstable:** سيرفرات t3 بتجمّع "رصيد CPU" وبتصرفه وقت الضغط، ولما يخلص بتبطّأ. أما c7i-flex فأداؤه ثابت، وهذا أنسب لبث متواصل 24 ساعة.

## قرار 11: الـ Bitrate = 128kbps MP3 (بث واحد)
- **التاريخ:** 2026-11-23
- **القرار:** تخفيض البث الأساسي `/radio.mp3` من 192kbps لـ 128kbps MP3.
- **السبب:**
  - التشخيص بيّن إن التقطيع سببه تذبذب الشبكة (Jitter) مع Buffer صغير بمشغّل المتصفح (حوالي ثانية).
  - 128kbps بيحتاج بيانات أقل بحوالي 33%، فبيتأثر أقل بالتذبذب، وبيوفّر من نت الفروع (حوالي 58MB بالساعة بدل 86MB).
  - 128kbps هو المعيار لأغلب إذاعات الإنترنت، والجودة كافية لموسيقى خلفية بمطعم.
  - MP3 بيشتغل على كل الأجهزة والمتصفحات.
- **البدائل:**
  | البديل | ليش ما اخترناه هلأ |
  |---|---|
  | إبقاء 192kbps | حساس أكثر للتذبذب، وبيستهلك نت أكثر بدون فرق واضح بالجودة لمطعم |
  | بثين (192 + 128 lite) من نفس المصدر | مرن، بس بيعقّد الإعداد. **متاح مستقبلاً** إذا احتاجت فروع معينة جودة أعلى أو أقل |
  | AAC / Opus بـ Bitrate أقل | جودة أحسن بحجم أقل، بس التوافق مع المتصفحات والأجهزة القديمة أقل من MP3 |

## قرار 12: البقاء على AWS وعدم النقل لـ Oracle قبل التسليم
- **التاريخ:** 2026-11-24
- **الخلفية:** حساب Oracle صار يفتح بعد ما انتهى الحظر المؤقت (Rate Limiting).
- **القرار:** نكمل على AWS للتسليم والتقييم، وOracle بيضل **خطة احتياطية وخيار لتوفير التكلفة** على المدى الطويل.
- **حصة السوق (Synergy Research Group، الربع الثالث 2026):** AWS بالمقدمة بحصة 26% ([المصدر](https://www.techinsights.com/node/61958)). أرقام Azure وGoogle وOracle الحديثة ما لقيتها منشورة كاملة؛ آخر أرقام وجدتها كانت Azure 20% وGoogle 13% وOracle 3% ([TechTarget عن Synergy](https://www.techtarget.com/searchCloudComputing/news/366634757/The-big-three-grab-two-thirds-of-107B-cloud-market-in-Q3))، وOracle من الأسرع نمواً.
- **المقارنة:**
  | الناحية | AWS | Oracle Cloud (OCI) |
  |---|---|---|
  | حصة السوق | الأكبر | صغيرة بس بتنمو |
  | مين بيستخدمه | كل أنواع الشركات (ناشئة، وتقنية، وبنوك، ومتاجر) | شركات كبيرة بتعتمد على قواعد بيانات Oracle (بنوك، وحكومات) |
  | سوق العمل | الأكثر طلباً بالوظائف والشهادات | مطلوب أقل |
  | تنوع الخدمات | الأكبر | أقل، وقوي بقواعد البيانات |
  | المجاني | رصيد مؤقت (100–200$ لمدة 6 شهور) | مجاني للأبد (ARM 2 OCPU / 12GB) |
  | السعر بعد المجاني | أغلى عادة | أرخص عادة، خصوصاً نقل البيانات |
  | سهولة الاستخدام | جدار ناري واحد (Security Group)، وتوثيق ومجتمع ضخم | جداران (Security List + iptables)، ومجتمع أصغر |
  | التسجيل | سلس | صعب أحياناً (تجربتنا مع الـ MFA) |
- **أسباب القرار:**
  1. AWS هو المعيار بالصناعة، واللجنة والشركات بتعرفه.
  2. النظام شغال ومجرّب ومشخّص على AWS، والنقل قبل التسليم بيوم مخاطرة بدون فايدة بالتقييم (**Risk Management**).
  3. رصيد AWS بيغطي فترة التقييم والمقابلة الثانية (وأطول إذا رجّعنا السيرفر لـ 2GB).
- **خطة مستقبلية:** للتشغيل الطويل بتكلفة صفر، بننقل لـ Oracle حسب الخطة الموثقة بـ infrastructure.md (Backup ← Restore ← تغيير الـ IP بـ DuckDNS)، **والرابط ما بيتغير**.

## قرار 13: معالجة الصوت (AutoDJ Audio Processing)
- **التاريخ:** 2026-11-24
| الإعداد | القيمة | السبب |
|---|---|---|
| Crossfade | Normal Mode، ثانيتين | انتقال ناعم بين الأغاني بدون صمت، ومناسب لجو مطعم |
| Post-processing | **Basic Normalization and Compression** | بيوحّد مستوى الصوت بين الأغاني، فالموظف ما بيضطر يغيّر الصوت بالفرع |
| AutoCue / ReplayGain | مطفيين | High CPU، ووظيفتهم مغطاة بالـ Basic Normalization |
| Master_me | لا | معالجة احترافية أثقل، وما بنحتاجها لموسيقى خلفية |
- **ملاحظة للتشغيل الفعلي:** Duplicate Prevention مضبوط على 120 دقيقة، بس المكتبة الحالية 40 دقيقة بس. للإنتاج لازم مكتبة موسيقى أكبر (عدة ساعات) لتقليل التكرار.

## قرار 15: Mount Point لكل فرع (لمراقبة اتصال الفروع)
- **التاريخ:** 2026-11-25
- **المشكلة:** الـ API العام بيعطي عدد المستمعين الكلي بس، وما بنعرف منه **أي فرع** متصل.
- **القرار:** Mount منفصل لكل فرع، **كلهم من نفس مصدر الـ AutoDJ**:
  | Mount | الفرع (أسماء للعرض التجريبي وقابلة للتعديل) |
  |---|---|
  | `/radio.mp3` | العام / الديمو (Default) |
  | `/abdoun.mp3` | غماس بلدي · فرع عبدون |
  | `/tabarbour.mp3` | غماس بلدي · فرع طبربور |
  | `/rabieh.mp3` | غماس بلدي · فرع الرابية |
- **الإعدادات:** نفس الصيغة (MP3 128kbps)، و**Share Encoders Between Streams = On** (الصوت بينضغط مرة وحدة)، وShow on Public Pages = Off، وYellow Pages = Off (بث داخلي ما بينعلن عنه)، وMax Listener Duration = 0 (ما في فصل دوري)، وFallback = /error.mp3.
- **ليش ما بيأثر على التزامن:** كل الـ Mounts بتاخذ نفس الصوت من نفس الـ Liquidsoap بنفس اللحظة.
- **البدائل اللي رفضناها:**
  | البديل | ليش رفضناه |
  |---|---|
  | مفتاح API الإدارة بصفحة عامة | خطر أمني: أي حدا بيقرأ الكود بياخذ صلاحيات الإدارة |
  | سيرفر Heartbeat (كل فرع بيبلّغ "أنا شغال") | الحل الصح لـ 100 فرع وأكثر، بس بيحتاج Backend وقاعدة بيانات، ومش واقعي قبل التسليم |
  | أرقام محاكاة بلوحة الإدارة | غير صادق، وبيضرب مصداقية النظام |
- **قابلية التوسع:** لعشرات الفروع، Mount لكل فرع مقبول. لـ 100 فرع وأكثر بننتقل لنظام Heartbeat.
